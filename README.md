# Мой Журнал

Локальный дневник для Android 14–16, `com.nsfr.myjournal`, версия **1.0.0 (1)**. Интерфейс на русском языке. Записи, фотографии и чернила остаются в памяти приложения; сетевых SDK и разрешения `INTERNET` нет.

## Использование

Календарь открывается при холодном запуске. Новую запись можно создать за сегодня или вчера; одновременно разрешён один черновик. Старый черновик можно продолжить и запечатать позднее. Изменения автоматически сохраняются через 300 мс; при уходе приложения в фон выполняется принудительная запись.

В режиме «Текст» вводите ответы под постоянно видимыми вопросами. Кнопка «Фото» открывает системный Photo Picker и вставляет изображение после абзаца с курсором. Нажатие на фото в черновике открывает выбор 50/75/100% и удаление; в запечатанной записи — полный экран.

«Вопросы» открывает изменение формулировок, порядка, добавление и архив. Непустой и последний вопросы убрать нельзя. Здесь же находится удаление черновика с подтверждением. Шаблон меняется только при запечатывании; настройки шаблона заблокированы на редактирование, пока есть черновик.

В режиме «Ручка» один палец рисует, два перемещают и масштабируют страницу от 1× до 3×. Основной цвет адаптируется к теме. Undo/redo сохраняются в Room. Геометрический распознаватель привязывает уверенные подчёркивания, зачёркивания и обводки к тексту; другие штрихи привязываются к ближайшему блоку. Пересекающее диапазон редактирование переводит пометку в свободную.

«Сохранить» требует отдельного подтверждения. Запечатанную запись нельзя изменить или удалить отдельно. Полная очистка в настройках требует двух подтверждений и точной фразы `УДАЛИТЬ ВСЁ`.

Экспорт в настройках сохраняет через системный выбор файла ZIP с `journal.pdf`, `journal.md` и `media/YYYY-MM-DD/`. Экспортируются только запечатанные записи. Импорта и восстановления архива в версии 1 нет.

## Сборка на Windows

Нужны JDK 21, Android SDK с платформой 36 и Build Tools 36.0.0, переменные `JAVA_HOME` / `ANDROID_HOME`. JVM target — 17. Проект использует AGP 9.2.0, Gradle 9.4.1, Compose plugin 2.3.21, KSP 2.3.9 и Ink 1.0.0. Wrapper взят из указанного локального проекта без копирования его исходников или toolchain.

```powershell
# Все команды из D:\projects\journaling.
$env:GRADLE_USER_HOME = "$PWD\.gradle-user-home"
# Только для первой сборки с новым ключом:
.\scripts\create-signing.ps1
.\gradlew.bat testDebugUnitTest lintDebug assembleRelease
# После подключения тестового телефона:
.\gradlew.bat connectedDebugAndroidTest
```

Можно использовать `.\scripts\build.ps1 testDebugUnitTest lintDebug assembleRelease`: скрипт сам задаёт локальный Gradle-кэш. `ANDROID_USER_HOME` не задаётся. Если используется `local.properties`, двоеточие Windows-диска экранируется: `sdk.dir=D\:/.../android-sdk`.

Готовый APK: `dist/MyJournal-1.0.0.apk`. Debug имеет отдельный package `com.nsfr.myjournal.debug`, чтобы инструментальные тесты не затронули личный release-дневник.

## Подпись

`local-signing/myjournal.p12`: отдельный RSA 4096, alias `myjournal`, PKCS12, срок 100 лет. Пароль создаётся системным криптографическим генератором и хранится в `local-signing/release.properties`. Секреты и APK исключены из Git. Release без ключа завершается понятной ошибкой, debug-подпись не используется.

**Сохраните весь каталог `local-signing/` отдельно в безопасном месте. Он необходим для установки будущих обновлений поверх текущего приложения.** Генератор отказывается перезаписывать существующий ключ.

## Архитектура и проверки

- `Data.kt`: Room v1, внешние ключи, уникальная дата и частичный SQLite-индекс единственного черновика. DAO скрывает универсальные вставки; публичные операции проверяют `DRAFT` в транзакции. Дата дополнительно защищена SQLite-триггером. Запечатывание и эволюция шаблона — одна транзакция.
- `JournalModel.kt`: состояние экрана, последовательная запись, debounce и сохранение в `onStop`; DataStore хранит тему, цвет и толщину.
- `EditorScreen.kt`: Compose/Material 3, непрерывная страница, системные insets, Photo Picker.
- `InkEngine.kt`, `Magnet.kt`: стабильный Ink marker V1, официальный сериализатор входных точек и Canvas renderer. Нативная поверхность Ink создаётся только в режиме ручки. Диапазоны переносятся по изменениям текста; reflow линий разделяет штрих по новым строкам, не создавая диагоналей между ними.
- `MediaStore.kt`: ImageDecoder применяет ориентацию; повторное кодирование пикселей удаляет EXIF. Максимальный размер 2560 px, миниатюра до 640 px; JPEG quality 90, PNG для прозрачности.
- `JournalExport.kt`: Android PdfDocument, A4, пагинация с клипованием обеих частей пересекающего страницу штриха, штатный Ink renderer, Markdown и ZIP.

Локальные тесты охватывают хранилище, ограничения черновиков, эволюцию и архив шаблона, восстановление Room, undo/redo, распознавание, reflow, обработку фото, Markdown, ZIP и расчёт пагинации. Compose-тесты на хосте проверяют основные экраны, автосохранение и подтверждение запечатывания; снимки находятся в `app/build/host-previews/`.

Реальная генерация PDF и нативный Ink дополнительно проверяются в `InkDeviceTest` на Android. Robolectric на этом Windows-хосте не создаёт нативный handle PdfDocument: локальный ZIP-тест проверяет упаковку PDF-файла, а не подменяет проверку настоящего рендеринга. Проверки телефона **отложены по просьбе пользователя**; их порядок — в [DEVICE-CHECKLIST.md](DEVICE-CHECKLIST.md). Плавность, zoom/pan, Photo Picker и работа Ink после R8 требуют этой проверки.

Отчёты: `app/build/test-results/testDebugUnitTest/TEST-*.xml`, `app/build/reports/lint-results-debug.xml`, `app/build/outputs/androidTest-results/connected/`. Скрипт [scripts/verify-artifact.ps1](scripts/verify-artifact.ps1) проверяет XML, копирует release APK в `dist`, проверяет подпись, package, версии, разрешения и SHA-256. Git-репозиторий локальный; remote не добавляется.
